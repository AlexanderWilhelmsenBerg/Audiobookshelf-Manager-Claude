# Security

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on this repository. Please do not open a public issue
for a security problem.

Include what you did, what happened, and what you expected. If the report involves a self-hosted
server, please redact its hostname — this project's own diagnostics do the same by default, and we do
not want your server address either.

## Invariants

These come from `PRODUCT_SPEC 15` and must not regress. A change that weakens one needs an ADR and an
explicit review, not a commit message.

**Transport**

- HTTPS by default. Release builds reject cleartext (`app/src/main/res/xml/network_security_config.xml`).
- Platform certificate trust only. There is no `sslSocketFactory` override, no custom
  `HostnameVerifier`, and no "trust all certificates" mode anywhere in this repository — including in
  debug builds, where such a switch is usually added and then forgotten.
- No certificate pinning by default: self-hosted certificates rotate, and pinning locks users out.
- A future custom-CA feature must use explicit certificate import and show the fingerprint.

**Credentials**

- Passwords are never persisted.
- Tokens are encrypted with Android Keystore-backed key material (`AUTH-003`). The database contains no
  raw tokens, and `AuthToken.toString()` is overridden so that interpolating the object holding one
  cannot print it.
- **`GET /api/users` returns every user's live token.** The app must never model that field: `UserDto`
  and `UserSummaryDto` have no `token` property, so there is nothing to store, log or display. Pinned by
  `CapturedShapesTest` — this is an invariant about a *response shape*, and the only way to keep it is to
  refuse to parse the field.
- Authorization is a header, never a query parameter generated by app code.
- Backup and device transfer are fully excluded (`app/src/main/res/xml/data_extraction_rules.xml`), so
  a restore cannot carry a token to another device or leave an undecryptable state.

**Logging and diagnostics**

- Tokens, cookies, passwords, hosts, usernames, media titles, descriptions and filesystem paths are
  redacted by default. See [ADR-0004](docs/adr/0004-redacted-structured-logging.md).
- Exception messages are never logged — only the exception-class chain — because
  `UnknownHostException`'s message is the hostname.
- No analytics and no crash reporting. Any future crash reporting is opt-in and strips private
  content.

**Destructive actions**

- `Remove from Audiobookshelf database` and `Delete source files` are separate operations with
  separate capabilities. The database-delete endpoint does not delete files, and no UI may say it
  does (`MGR-005`, `MGR-006`, `PRODUCT_SPEC 22.12`).
- **True source-file deletion ships no feature at all**, and that is a decision rather than an omission.
  `MGR-006` requires a server response that explicitly confirms the deletion; Audiobookshelf logs a
  failed filesystem removal server-side and discards it, so the request succeeds either way and no
  capture can distinguish the two. [ADR-0021](docs/adr/0021-source-file-deletion-ships-no-feature.md)
  records the reasoning and `ManagementActionTest` guards it.
- **Embedding metadata rewrites the user's source audio files** (`MGR-007`). One item at a time, never
  the batch endpoint, and always with the server's own backup requested — never a toggle. A mis-tap that
  rewrites one book is recoverable; one that rewrites a library may not be.

**Build**

- Every dependency version is pinned; repositories are restricted and content-filtered.
- Dependency verification is **strict**, over 887 pinned components with SHA-256 checksums generated
  against the resolved version set. An artifact whose checksum is absent or wrong fails the build rather
  than warning. `verify-signatures` stays false because several AndroidX and Google artifacts are
  unsigned; see [ADR-0006](docs/adr/0006-dependency-locking-and-verification.md).
- CI validates the Gradle wrapper and scans for secrets on every pull request.
- No production secrets in the repository. There is no signing configuration.

## Supported versions

Pre-release. No version is supported for security updates yet, and there is no distribution channel to
ship one through — `LICENSE` and the channel are both open decisions (`PRODUCT_SPEC 24`). The first
release will name a supported version here.

## What has not been verified

Stated because an invariant nobody has tested is a claim, not a guarantee. The transport, credential and
logging invariants above are enforced by tests that run on every pull request. These are not:

- **No instrumented test exists.** The whole UI tier is Robolectric on the JVM at API 34; `minSdk` is 26.
- **The release build is assembled but never launched**, so R8's effect on reflection-shaped code —
  Room, Hilt, Media3, serialization — is unexercised.
- **Two of the management contracts are derived from the server's source rather than captured**, because
  they need permissions the public demo account does not hold: cover upload and embed metadata.

`docs/risks.md` carries the full accounting, with the cheapest thing that would retire each one.
